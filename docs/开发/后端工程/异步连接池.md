# 异步连接池
异步连接池是在异步编程模型中管理可复用连接（数据库、HTTP、Redis 等）的组件。核心思想：
## 为什么需要它
创建连接（TCP 握手、认证等）开销大。连接池预先创建一批连接，请求到来时借出，用完归还，避免反复创建/销毁。
## 与同步连接池的区别
同步池中，线程阻塞等待连接可用；异步池中，协程 `await` 等待，不阻塞事件循环，单线程即可支撑高并发。
## 典型工作流程
```plain text
1. 初始化：创建 min_size 个连接放入空闲队列
2. 获取：await pool.acquire() → 有空闲连接则直接返回，否则：
   - 未达 max_size → 创建新连接
   - 已达上限 → 挂起协程，等待其他协程归还
3. 归还：pool.release(conn) → 连接回到空闲队列，唤醒等待者
4. 健康检查：定期剔除断开/超时的连接
```
## Python 示例（asyncpg）
```python
import asyncpg

pool = await asyncpg.create_pool(
    dsn="postgresql://user:pass@localhost/db",
    min_size=5,
    max_size=20,
    max_inactive_connection_lifetime=300,  # 空闲超时
)

async with pool.acquire() as conn:
    row = await conn.fetchrow("SELECT * FROM users WHERE id=$1", 1)
```
## 关键参数
| 参数 | 作用 |
| --- | --- |
| `min_size` | 最小保持连接数 |
| `max_size` | 最大连接数，超出则排队 |
| `max_idle_time` | 空闲连接超时回收 |
| `max_lifetime` | 连接最大存活时间，防止长连接劣化 |
## 常见实现
- 数据库：`asyncpg`、`aiomysql`、SQLAlchemy async engine
- HTTP：`aiohttp.ClientSession`（内部自带连接池）、`httpx.AsyncClient`
- Redis：`redis.asyncio.ConnectionPool`
## 注意事项
- **连接泄漏**：务必用 `async with` 或 `try/finally` 确保归还
- **池大小调优**：太小导致排队延迟，太大浪费资源且可能打满数据库 `max_connections`
- **连接失效**：网络抖动后需要重连机制，好的池实现会在 acquire 时做 ping 检测
