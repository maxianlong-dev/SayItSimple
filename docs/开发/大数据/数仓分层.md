# 数仓分层
好，用大白话讲清楚**为什么要分层**，以及每层到底干嘛。
---
## 一、先说结论：为什么要分层？
**核心原因一句话：不分层，数据会乱成一锅粥，改一次崩一片。**
想象一个**餐厅后厨**：
```plain text
如果不分层 = 一个厨师从买菜、洗菜、切菜、炒菜、摆盘全干
           → 100 道菜就要重复洗切 100 次，累死且乱

分层     = 采购组买菜 → 清洗组洗 → 切配组切 → 炒菜组炒 → 摆盘组装盘
           → 洗好的菜，红烧肉能用、糖醋排骨也能用，一次洗多次用
```
数仓分层就是**把"从原始数据到最终报表"这条流水线，切成几段，每段专人负责**。
---
## 二、不分层会有什么惨状？
| 不分层的问题 | 具体表现 |
| --- | --- |
| **重复计算** | 100 个报表都要从原始表算一遍"用户数"，浪费算力 |
| **口径不统一** | A 报表算的 GMV 和 B 报表不一样，老板问谁对？ |
| **牵一发动全身** | 源头表字段一改，几百个报表全挂 |
| **没法排查** | 数据错了，从头到尾一大坨 SQL，不知道哪错了 |
| **重复劳动** | 每个人都从零开始洗数据，做了无数遍相同的活 |
---
## 三、四层分别是什么（从下往上）
```plain text
ADS  应用层    → 炒好摆盘的菜，直接端给客人（报表）
 ↑
DWS  汇总层    → 半成品：切好配好的菜（按主题汇总）
 ↑
DWD  明细层    → 洗干净的菜（清洗过的干净明细）
 ↑
ODS  贴源层    → 刚买回来带泥的菜（原始数据照抄）
 ↑
     业务系统（MySQL 等原始数据源）
```
### ① ODS（贴源层 / Operational Data Store）
- **干嘛的**：把业务库的数据**原样抄一份**过来，不做任何加工。
- **为什么要**：给数仓一个"缓冲垫"，不去直接骚扰线上业务库；同时保留原始快照，出错了能回溯。
- **比喻**：菜市场买回来的菜，带着泥，先堆仓库。
### ② DWD（明细层 / Data Warehouse Detail）
- **干嘛的**：**清洗**。去重、去脏数据、补空值、统一格式、字段改成好懂的名字。
- 数据粒度还是**最细的**（一行还是一笔订单）。
- **为什么要**：脏活累活干一次，后面所有人用干净的数据。
- **比喻**：把菜洗干净、择好。
### ③ DWS（汇总层 / Data Warehouse Summary）
- **干嘛的**：**按主题做轻度汇总**。比如"每个用户每天的下单次数、消费金额"。
- 粒度变粗了（从"每笔订单"变成"每人每天"）。
- **为什么要**：常用的统计提前算好，别每次都从明细现算。
- **比喻**：把菜切好、配好料，做成半成品。
### ④ ADS（应用层 / Application Data Store）
- **干嘛的**：**直接给报表/大屏用的最终结果**。比如"全站每日 GMV 趋势"。
- 高度聚合，一张表对应一个具体业务需求。
- **比喻**：炒好摆盘，直接端上桌。

## 四、用一个真实例子串起来
需求：老板要看\*\*"每天各城市的销售额报表"\*\*
```plain text
① ODS：把 MySQL 的订单表原样同步过来
   ods_order（含脏数据、测试订单、字段是拼音缩写）

② DWD：清洗
   dwd_order（去掉测试订单、剔除退款、city_id 关联出城市名、金额单位统一）
   → 还是一笔一行

③ DWS：按"城市+天"汇总
   dws_city_sales_day（杭州 2026-09-23 销售额 500万，订单数 2万）
   → 一城市一天一行

④ ADS：直接出报表要的结果
   ads_city_sales_report（给 BI 直接读，加了同比环比、排名）
   → 端给老板看
```
**关键好处**：如果明天又要做"各城市销售额大屏"，直接复用 DWS 那层，不用从头再洗一遍！

## 五、分层带来的 5 大好处（总结）
| 好处 | 说明 |
| --- | --- |
| **① 复用** | 洗一次、汇总一次，多个报表共用，不重复造轮子 |
| **② 解耦** | 源头改了只影响 ODS，往上层层隔离，不会全崩 |
| **③ 口径统一** | GMV 只在 DWS 算一次，全公司用同一个，不打架 |
| **④ 好排查** | 数据错了，一层层往下查，快速定位是哪层的锅 |
| **⑤ 省算力** | 中间结果存下来，避免每次从头算 PB 级数据 |

## 一、CDM 是什么
**CDM = Common Data Model，公共维度模型层（也叫"公共层"/"中间层"）。**
关键点：**CDM 不是第五层，它其实就是把前面讲的 DWD + DWS 打包合在一起的一个大层。**
---
## 二、阿里的分层 vs 通用分层（对照表）
| 通用叫法 | 阿里叫法 | 里面装啥 |
| --- | --- | --- |
| ODS | **ODS** | 贴源层，原始数据照抄 |
| DWD + DWS | **CDM**（公共层） | 清洗 + 汇总，公共复用 |
| ADS | **ADS**（也叫 APP/DM） | 应用层，直接给报表 |
所以阿里体系里，你会听到：**ODS → CDM → ADS** 三大层。
而 **CDM 内部又拆成两块**（就是之前讲的 DWD/DWS）：
```plain text
CDM 公共层
 ├── DWD  明细层：清洗后的干净明细
 └── DWS  汇总层：按主题的轻度汇总

有些团队 CDM 里还会再分一个：
 └── DIM  维度层：专门放维度表（城市表、商品表、用户表）
```
---
## 三、CDM 这个名字的重点在哪？—— "Common（公共）"
**CDM 的灵魂就是"公共"两个字。**
它存在的意义：**把大家都要用的、通用的数据加工好，放在这一层，谁都能来取，避免重复干活。**
```plain text
                    ┌─→ ADS 报表A（销售大屏）
                    │
CDM 公共层（一次加工）├─→ ADS 报表B（城市分析）
"每城市每天销售额"    │
                    └─→ ADS 报表C（同比环比）

如果没有 CDM：报表 A/B/C 各自从 ODS 原始数据洗一遍 → 重复三次、口径还可能不一致
```
---
## 四、放进完整链路里看
```plain text
     业务系统 MySQL
        ↓ 照抄
   ODS  贴源层
        ↓ 清洗、汇总（公共加工，一次做好大家共用）
   CDM  公共层  ┌ DWD 明细
              ├ DWS 汇总
              └ DIM 维度
        ↓ 按具体需求出结果
   ADS  应用层  → 报表 / 大屏
```
---
## 五、一句话记忆
> **CDM = 公共层 = DWD + DWS 的打包，核心是"Common 公共"：通用数据在这一层加工一次，所有报表共享，不重复劳动。**
简单说：**你之前问的 DWD、DWS，在阿里体系里被装进了 CDM 这个大盒子。**
