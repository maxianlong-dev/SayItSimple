# 进程、线程与协程
可以把它们理解成：计算机为了“同时处理很多事情”而采用的三种不同层级的执行方式。
## 程序与进程
**程序**是硬盘上的静态文件，例如微信、浏览器或一个 Python 脚本。
**进程**是程序运行起来后的实例。操作系统会给每个进程分配：
- 独立的虚拟内存
- 代码和数据
- 文件、网络连接等资源
- 至少一个线程
例如启动两个 Chrome，它们可能产生许多相互隔离的进程。一个进程崩溃，通常不会直接破坏其他进程。
进程隔离性强，但创建、切换和通信的成本较高。进程之间通常通过管道、Socket、共享内存等 IPC 机制通信。
## 线程
**线程是进程内部真正执行代码的基本单位。**
一个进程可以包含多个线程，它们：
- 共享进程的内存和文件资源
- 各自拥有调用栈、寄存器和程序计数器
- 可以由操作系统调度到不同 CPU 核心并行运行
例如浏览器可以用不同线程处理界面、网络和计算。
共享内存让线程通信很方便，但也产生并发安全问题：
```plain text
线程 A：读取余额 100
线程 B：读取余额 100
线程 A：扣除 20，写入 80
线程 B：扣除 30，写入 70
```
正确结果应该是 50，实际却可能变成 70。这叫**竞态条件**。通常需要互斥锁、信号量、原子操作等机制保护共享数据，但使用不当又可能造成死锁。
## 协程
**协程是运行在线程之上的轻量级任务。**
它通常由语言运行时或程序自己调度，而不是直接由操作系统调度。协程执行到网络请求、定时器等等待点时，可以主动暂停，把线程让给其他协程：
```python
async def get_data():
    result = await request()
    return result
```
`await` 的大致含义是：
> 这个操作需要等待，先暂停我，让同一线程处理其他任务；结果到达后再继续。
协程的创建和切换通常比线程便宜，因此一个线程可能管理成千上万个协程。它特别适合：
- Web 服务
- 网络爬虫
- 即时通信
- 大量数据库或网络请求
但协程不会自动让 CPU 计算变快。如果一个协程长时间计算而不让出执行权，同一线程里的其他协程都会被阻塞。
## 三者关系
```plain text
操作系统
└── 进程：拥有独立资源和内存
    ├── 线程：由操作系统调度执行
    │   ├── 协程 A：由运行时调度
    │   ├── 协程 B
    │   └── 协程 C
    └── 线程
```
| 特征 | 进程 | 线程 | 协程 |
| --- | --- | --- | --- |
| 调度者 | 操作系统 | 操作系统 | 程序或语言运行时 |
| 内存 | 相互隔离 | 共享进程内存 | 通常共享线程内存 |
| 创建与切换成本 | 高 | 中 | 低 |
| 多核并行 | 可以 | 通常可以 | 单线程内通常不可以 |
| 故障隔离 | 强 | 弱 | 弱 |
| 适合场景 | 隔离、CPU 计算 | 并行计算、同步任务 | 高并发 I/O |
## 并发与并行
- **并发**：多个任务交替推进，看起来同时发生
- **并行**：多个任务真的在不同 CPU 核心上同时执行
例如一个厨师交替炒菜和煮汤是并发；两个厨师分别炒菜和煮汤是并行。
协程擅长并发；多进程和多线程可以利用多核实现并行。
## 如何选择
- CPU 密集型任务，如图片处理、科学计算：多进程或能真正多核执行的多线程
- I/O 密集型任务，如网络、数据库请求：协程或线程
- 需要强隔离、避免互相影响：多进程
- 任务量巨大且多数时间在等待：协程
- 简单程序：优先保持单线程，不必刻意引入并发
## 总结
> 进程是资源容器，线程是操作系统执行单位，协程是用户态轻量任务；多进程重隔离，线程重并行，协程重高并发等待。
