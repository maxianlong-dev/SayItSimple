# 计算机网络
## 1. 分层模型：为啥要分层？
**大白话**：网络太复杂，一个人干不完，就像开餐厅——采购、洗菜、炒菜、上菜分开做。每层只管自己那摊事，坏了也好排查。
**例子**：你在饿了么点一份麻辣烫
- 应用层（HTTP）= 你和商家沟通"我要微辣不要香菜"
- 传输层（TCP）= 快递小哥保证送到、送全
- 网络层（IP）= 导航告诉小哥怎么走
- 链路层 = 电动车、马路本身
你换个 App（美团），只需要换"应用层"，下面照用不误 —— 这就是**分层解耦**的好处。
### OSI 七层 vs TCP/IP 四层
| OSI 七层 | TCP/IP 四层 | 干什么 |
| --- | --- | --- |
| 应用层 / 表示层 / 会话层 | 应用层 | 你看到的东西（HTTP、DNS、FTP） |
| 传输层 | 传输层 | 端到端可靠 or 不可靠传输（TCP / UDP） |
| 网络层 | 网络层 | 选路、寻址（IP） |
| 数据链路层 / 物理层 | 链路层 | 物理传输（网线、WiFi、MAC 地址） |
> **面试考点**：实际开发只用 TCP/IP 四层模型，OSI 七层是教科书分法，能说出区别即可。

## 2. IP 地址 & MAC 地址
**大白话**：
- **MAC 地址** = 你的身份证号，出厂就定死（48 位，如 `AA:BB:CC:DD:EE:FF`）
- **IP 地址** = 你现在住哪里，搬家就变（IPv4 是 32 位，如 `192.168.1.100`）
**例子**：你从北京搬到杭州
- 身份证号不变（MAC 不变）
- 收快递的地址变了（IP 变了）
快递员要送快递，看的是**地址（IP）**；到了小区门口保安核对**身份证（MAC）**放你进门。
### ARP：IP → MAC 的翻译员
**大白话**：小区门口喊一嗓子——"喂，IP 是 192.168.1.5 的哥们，报下你身份证号"，本人应答。
### 子网 & CIDR
**大白话**：IP 地址分"小区号"和"门牌号"。
- `192.168.1.0/24` → 前 24 位是小区号，后 8 位是门牌号 → 这个小区最多住 254 户
- `/16` → 后 16 位做门牌号 → 能住 65534 户（大小区）
### 私有 IP & NAT
**大白话**：小区内部用 1 栋 2 栋的编号（私有 IP），出小区上公路要换成真实门牌号（公网 IP）。
**例子**：你家 WiFi 下所有设备都是 `192.168.x.x`（私有 IP），访问外网时路由器帮你换成运营商给的公网 IP——这个"换号"过程就是 **NAT（网络地址转换）**。
### IPv6
- 128 位地址，空间大到给地球每粒沙子都能分一个
- 不再需要 NAT
- 写法示例：`2001:0db8:85a3::8a2e:0370:7334`

## 3. 路由：包怎么找到去处？
**大白话**：包裹在快递网络里一站站中转，每个中转站看包裹上的地址，查自己的路线表决定往哪送。
**例子**：北京寄快递到杭州
```plain text
你家 → 朝阳区分拨中心 → 北京总仓 → 华东总仓 → 杭州分拨 → 收件人
```
每个分拨中心 = 路由器，路线表 = 路由表，只看"目的地城市"做决策。
- **OSPF**：同一个快递公司内部选最优路线（内部网关协议）
- **BGP**：不同快递公司之间协商路线（运营商之间用）

## 4. TCP 三次握手
**大白话**：确认双方"我能听见你，你也能听见我"。
**例子**：打电话
```plain text
A: "喂，能听见吗？"           → SYN（seq=100）
B: "能听见，你能听见我吗？"    → SYN+ACK（seq=200, ack=101）
A: "能听见，开始说正事"        → ACK（seq=101, ack=201）
```
**为啥不能两次？**
想象你发短信约人吃饭，消息堵了半小时才到，对方直接冲到饭店——你没去，尴尬了。三次握手让 A 最后再确认一次，避免历史消息造成"幽灵连接"。

## 5. TCP 四次挥手
**大白话**：分手要客气，一方说完不等于另一方说完。
```plain text
A: "我说完了，挂了啊"          → FIN
B: "收到，等我把最后一句说完"   → ACK
B: "好，我也说完了"             → FIN
A: "行，拜拜"                   → ACK → 进入 TIME_WAIT
```
### TIME_WAIT：为啥要等 2×MSL？
**大白话**：A 挂完电话后还愣 60 秒才放下听筒。
原因有两个：
1. 万一最后那个"拜拜"（ACK）B 没收到，B 会重发 FIN，你还能回复
2. 确保网络上属于这次通话的所有"余音"彻底消散，不会被下一次通话捡到
> MSL = Maximum Segment Lifetime（包在网络中的最大存活时间），一般 30 秒。2×MSL 保证一来一回的老包都过期。

## 6. TCP 可靠传输
**大白话**：像发一整套漫画书，每本编号，收到要签收，丢了要补寄。
| 机制 | 大白话 | 例子 |
| --- | --- | --- |
| 序列号 | 每本贴编号 1-10 | 知道哪本丢了 |
| 确认应答 | 你签收"收到第 5 本了" | 卖家知道 1-5 都到了 |
| 超时重传 | 3 天没签收，重发 | 包裹丢件的补救 |
| 快速重传 | 你连续说 3 次"第 3 本没到！" | 不用等超时，立刻重寄 |
| 滑动窗口 | 一次最多发 4 本，签收 1 本再发 1 本 | 免得堆满你家门口 |
### TCP 粘包
**大白话**：TCP 是水管——你倒两杯水进去，对面只看到一管水流出来，分不清哪杯是哪杯。
**解决**：
- **定长**：每杯固定 200ml，数着接
- **分隔符**：两杯水之间加一滴墨（如 `\r\n`）
- **长度前缀**：先告诉对面"第一杯 200ml"（最常用，如 HTTP 的 `Content-Length`）

## 7. 拥塞控制
**大白话**：高速堵车了，你不能猛踩油门，得慢慢试探。
| 阶段 | 大白话 | 类比 |
| --- | --- | --- |
| 慢启动 | 1→2→4→8 指数加速 | 刚上高速，从 20 码逐步加到 120 |
| 拥塞避免 | 到一定速度后每次 +1 | 快到限速了，一码一码加 |
| 丢包/超时 | 紧急降速 | 前面出事故了，踩刹车 |
| 快恢复 | 降一半速继续 | 事故清了，恢复到限速的一半 |
**BBR 算法**（Google 出品）：不看"有没有撞车"来判断堵不堵，而是实时估算"这条路最多跑多快"，更聪明。

## 8. UDP vs TCP
| 对比 | TCP | UDP |
| --- | --- | --- |
| 大白话 | 挂号信，必须签收 | 明信片，扔了就不管 |
| 连接 | 需要（三次握手） | 不需要 |
| 可靠性 | 保证不丢不乱 | 不保证 |
| 速度 | 相对慢 | 快 |
| 头部大小 | 20 字节起 | 8 字节 |
| 场景 | 转账、网页、文件 | 直播、游戏、DNS |
**例子**：
- 转账用 TCP —— 一分钱都不能少
- 直播用 UDP —— 丢一帧无所谓，卡顿才要命
- 视频通话听到"滋滋"杂音 = UDP 丢了几个包

## 9. DNS：域名解析
**大白话**：把人名翻译成手机号。你记不住 `142.250.72.14`，但记得住 `google.com`。
### 解析流程
```plain text
浏览器缓存 → 系统 hosts 文件 → 本地 DNS 服务器 → 根 DNS → .com 顶级 DNS → google.com 权威 DNS
                                                                                    ↓
                                                                              返回 IP: 142.250.72.14
```
### 常见记录类型
| 类型 | 干什么 | 例子 |
| --- | --- | --- |
| A | 域名 → IPv4 | `google.com → 142.250.72.14` |
| AAAA | 域名 → IPv6 | `google.com → 2404:6800:...` |
| CNAME | 域名 → 另一个域名（别名） | `www.google.com → google.com` |
| MX | 邮件服务器 | 发邮件时找哪个服务器 |
| TXT | 文本信息 | 常用于 SPF 反垃圾邮件验证 |
**TTL** = 电话本里写"此号码 1 小时内有效"，过期要重新问。

## 10. HTTP 协议
### 请求方法
| 方法 | 大白话 | 幂等？ |
| --- | --- | --- |
| GET | 查数据 | 是（查多少次都一样） |
| POST | 提交新数据 | 否（每次提交都新建） |
| PUT | 整体替换 | 是（覆盖，结果一样） |
| PATCH | 局部修改 | 否（不保证） |
| DELETE | 删除 | 是（删了就没了，再删还是没了） |
> **幂等**：同一个操作执行 1 次和执行 N 次，效果一样。面试常问。
### 状态码
| 范围 | 大白话 | 常见 |
| --- | --- | --- |
| 2xx | 成功 | 200 OK、201 Created、204 No Content |
| 3xx | 转一下 | 301 永久搬家、302 临时搬家、304 没变过直接用缓存 |
| 4xx | 你的问题 | 400 请求有误、401 没登录、403 没权限、404 找不到、429 请求太频繁 |
| 5xx | 我的问题 | 500 服务器崩了、502 网关挂了、503 过载了、504 网关超时 |
### HTTP 版本演进
**大白话**：从"排队打饭"到"多窗口同时打饭"到"外卖直接送到桌"。
| 版本 | 关键改进 | 食堂类比 |
| --- | --- | --- |
| HTTP/1.1 | 持久连接、管线化 | 一个窗口排队，前面的人钱包找不到→全队卡住（队头阻塞） |
| HTTP/2 | 二进制分帧、多路复用、头部压缩 | 一个窗口同时喊多个菜号，厨房并行做 |
| HTTP/3 | 基于 QUIC（UDP） | 换赛道，一个菜出问题不影响其他菜上桌 |

## 11. HTTPS / TLS
**大白话**：给包裹加密 + 验明正身。
### TLS 握手过程（简化版）
```plain text
客户端 → "你好，我支持这些加密方式"        (ClientHello)
服务端 → "用这种加密，这是我的证书"         (ServerHello + Certificate)
客户端 → 验证证书 → 用公钥加密一个"暗号"发过去
双方 → 用"暗号"生成对称密钥 → 后续通信全用对称加密
```
### 为啥混合使用两种加密？
| 类型 | 速度 | 安全交换密钥 | 用途 |
| --- | --- | --- | --- |
| 非对称加密（RSA/ECDHE） | 慢 | 能 | 握手时交换"暗号" |
| 对称加密（AES） | 快 | 不能（密钥怎么安全传？） | 传数据 |
**例子**：用防弹押运车（非对称）送一把普通钥匙给你朋友，之后你俩用这把普通钥匙（对称）开同一个锁来传信。天天用防弹车太贵了，所以只用一次。
### 证书链
```plain text
根 CA（系统预装）→ 中间 CA → 你的网站证书
```
浏览器一级级验，只要根 CA 可信，整条链就可信。像公证处签字盖章的逐级授权。

## 12. Cookie / Session / JWT
HTTP 本身**无状态**——服务员每次都不认识你。怎么让他记住你？
| 方案 | 大白话 | 优缺点 |
| --- | --- | --- |
| Cookie | 服务员给你贴个纸条"7 号桌"，你每次来都亮纸条 | 存在浏览器，容量小（4KB），有 CSRF 风险 |
| Session | 服务员在本子上记"7 号桌 = 张三"，你只拿一个号 | 状态存服务端，多台服务器要共享 Session |
| JWT | 给你一张"防伪名片"，上面写名字+签名 | 无状态，服务端不存东西；但签发后无法主动失效 |
**例子**：
- Cookie = 游乐园手上盖的荧光章（你带着）
- Session = 游乐园入口的登记簿（园方带着，你只拿号码手环）
- JWT = 游乐园给你一张防伪门票（上面印了你的信息，验票只需看防伪标记，不用查登记簿）

## 13. WebSocket
**大白话**：HTTP 是"你问我答"，WebSocket 是"开了一条电话线，双方随时说话"。
**例子**：
- HTTP 轮询 = 你每 3 秒打电话问"有新消息吗？" → 费电话费
- WebSocket = 电话一直不挂，有消息直接说 → 实时聊天、股票行情、协同编辑
连接建立过程：先走一次 HTTP 握手（`Upgrade: websocket`），成功后协议"升级"，后续双向通信。

## 15. CDN（内容分发网络）
**大白话**：把货放到全国各地的仓库，用户就近取货，不用跨越半个中国。
**例子**：你在杭州看 B 站视频
- 没有 CDN：视频从北京总部传过来 → 慢
- 有 CDN：视频缓存在杭州机房 → 直接看，快
**工作流程**：
```plain text
1. 你访问 video.bilibili.com
2. DNS 解析 → 返回离你最近的 CDN 节点 IP
3. CDN 节点有缓存 → 直接返回
4. 没缓存 → CDN 去源站拉一份，缓存后返回给你
```

## 16. 负载均衡
**大白话**：一家火锅店太火，开了 5 家分店，门口保安决定你去哪家。
### 常见策略
| 策略 | 大白话 |
| --- | --- |
| 轮询 | 1 号、2 号、3 号、1 号、2 号… |
| 加权轮询 | 3 号店大，多分点客人 |
| 最少连接 | 哪家排队最少去哪家 |
| IP Hash | 根据你的 IP 固定去一家（保证 Session 一致） |
| 一致性哈希 | 加减分店时只影响最少的客人（常用于分布式缓存） |

## 17. CORS（跨域资源共享）
**大白话**：浏览器的"同源策略"像小区保安——不是本小区的人不让进。CORS 是物业开的通行证。
**例子**：你的前端在 `a.com`，要请求 `b.com` 的 API
```plain text
浏览器：你不是 b.com 的人，不让访问！
b.com 响应头加了：Access-Control-Allow-Origin: a.com
浏览器：哦，b.com 同意了，放行。
```
**简单请求**直接发；**复杂请求**（如 PUT、带自定义 Header）先发一个 OPTIONS 预检请求问"我能来吗？"

## 18. 网络安全常见攻击
### XSS（跨站脚本）
**大白话**：有人在留言板写了一段恶意代码，你一打开就中招。
**例子**：评论区有人写 `<script>偷你Cookie</script>`，你的浏览器傻乎乎执行了。
**防御**：对用户输入做 HTML 转义、使用 CSP 策略。
### CSRF（跨站请求伪造）
**大白话**：你登录了银行网站，骗子诱导你点了一个链接，浏览器自动带着你的 Cookie 去银行转账。
**例子**：你登录了银行 → 浏览了一个钓鱼网站 → 网站里藏了 `<img src="bank.com/transfer?to=hacker&amount=1000">`
**防御**：CSRF Token、SameSite Cookie、Referer 检查。
### 中间人攻击（MITM）
**大白话**：你和朋友打电话，有人偷偷接了分线，你俩都不知道。
**防御**：HTTPS（TLS 验证证书，防止冒充）。
### SQL 注入
**大白话**：你在登录框填 `' OR 1=1 --`，数据库以为这是合法查询，直接让你进。
**防御**：参数化查询（PreparedStatement），永远不要拼接 SQL。

## 19. Socket 编程
**大白话**：Socket 是操作系统提供的"电话机"。TCP/UDP 是通信规则，Socket 是让你打电话的工具。
```plain text
服务端                              客户端
socket()  创建电话机                socket()  创建电话机
bind()    绑定电话号码
listen()  开始等电话
accept()  接起电话     ←连接→      connect() 拨打电话
recv()    听           ←数据→      send()    说
send()    说           ←数据→      recv()    听
close()   挂电话                    close()   挂电话
```

## 22. 经典面试题精选
### Q1：从浏览器输入 URL 到看到页面发生了什么？
```plain text
1. URL 解析：判断是搜索还是网址
2. DNS 查询：域名 → IP（浏览器缓存 → 系统 → 本地 DNS → 递归查询）
3. TCP 三次握手：建立连接
4. TLS 握手：协商加密（如果是 HTTPS）
5. HTTP 请求：GET / HTTP/1.1
6. 服务器处理 + 响应：返回 HTML
7. 浏览器渲染：解析 HTML → 构建 DOM → 下载 CSS/JS/图片 → 布局 → 绘制
8. TCP 四次挥手：断开连接（keep-alive 除外）
```
### Q2：TCP 为啥不能两次握手？
两次握手下，如果客户端一个过期的 SYN 到达服务端，服务端直接建连分配资源 → 客户端根本不知道 → 资源白白浪费。第三次握手让客户端确认"我真的要连"。
### Q3：GET 和 POST 区别？
|  | GET | POST |
| --- | --- | --- |
| 语义 | 获取资源 | 提交数据 |
| 参数 | URL 里（?key=value） | Body 里 |
| 长度 | 浏览器有限制（约 2KB-8KB） | 无限制 |
| 缓存 | 会被缓存 | 不会 |
| 幂等 | 是 | 否 |
| 书签 | 可以保存 | 不行 |
> 技术上 GET 也能带 Body，POST 也能用 URL 参数，但不推荐。
### Q4：HTTP 和 HTTPS 区别？
|  | HTTP | HTTPS |
| --- | --- | --- |
| 端口 | 80 | 443 |
| 加密 | 明文传输 | TLS 加密 |
| 证书 | 不需要 | 需要 CA 证书 |
| 性能 | 稍快 | 多一次 TLS 握手（但 TLS 1.3 已很快） |
| 安全 | 裸奔 | 防窃听、防篡改、防冒充 |
### Q5：TCP 和 UDP 该怎么选？
- **要可靠性**（文件传输、网页、API）→ TCP
- **要速度和实时性**（视频通话、游戏、DNS）→ UDP
- **要可靠 + 快**（HTTP/3）→ QUIC（在 UDP 上实现可靠性）
