# 前端框架梳理
---
## 零、先搞清楚前端"框架"到底有几层
很多人说"前端框架"时，混着说了好几层东西。其实前端技术栈是这样分层的：
```plain text
┌─────────────────────────────────────────────────┐
│  ⑥ 跨平台方案        Taro / uni-app / RN / Flutter │
├─────────────────────────────────────────────────┤
│  ⑤ 上层框架（Meta）   Next.js / Nuxt / Astro       │
├─────────────────────────────────────────────────┤
│  ④ 状态管理          Zustand / Pinia / Redux       │
├─────────────────────────────────────────────────┤
│  ③ 组件库            Ant Design / Element Plus     │
├─────────────────────────────────────────────────┤
│  ② CSS 方案          Tailwind / UnoCSS / CSS Modules│
├─────────────────────────────────────────────────┤
│  ① UI 框架（核心）    React / Vue / Angular / Svelte │
├─────────────────────────────────────────────────┤
│  ⓪ 构建工具          Vite / Webpack / Turbopack     │
└─────────────────────────────────────────────────┘
```
下面逐层梳理。
---
## 一、⓪ 构建工具（Build Tools）
> 把你写的 JSX、TypeScript、Sass、Vue SFC 等**编译/打包**成浏览器能跑的 HTML/CSS/JS。
| 工具 | 特点 | 状态 |
| --- | --- | --- |
| **Vite** | 开发秒启动（ESM），生产用 Rollup 打包，当前主流 ⭐ | 首选 |
| **Webpack** | 老牌王者，插件生态最全，配置复杂 | 维护中，老项目在用 |
| **Turbopack** | Vercel 出品（Rust），Next.js 14+ 内置 | 快速发展中 |
| **Rollup** | 库打包首选，Tree-shaking 最早的实现 | 稳定 |
| **esbuild** | 极快（Go 写的），Vite 底层用它做预构建 | 工具链底座 |
| **Rspack** | 字节出品（Rust），兼容 Webpack API，快很多 | 快速发展中 |
```bash
# 用 Vite 创建项目（最常见）
npm create vite@latest my-app -- --template react-ts
npm create vite@latest my-app -- --template vue-ts
```
### 一句话选型
- **新项目** → Vite
- **老项目迁移** → Rspack（兼容 Webpack 配置）
- **打包库/组件** → Rollup / tsup
- **Next.js 项目** → Turbopack（内置）

## 二、① UI 框架（核心层 —— 最重要的选择）
> 决定你用什么方式写组件、管状态、更新 DOM。**选了它，上层的组件库、Meta 框架、状态管理都跟着走。**
### 主流四大框架对比
| 框架 | 出品 | 核心思想 | 模板语法 | 学习曲线 | 生态规模 |
| --- | --- | --- | --- | --- | --- |
| **React** | Meta (Facebook) | UI = f(state)，JSX，虚拟 DOM | JSX | 中 | ★★★★★ |
| **Vue** | 尤雨溪（社区） | 渐进式，响应式，SFC 单文件组件 | 模板 + JSX | 低 | ★★★★☆ |
| **Angular** | Google | 全家桶，TypeScript 优先，依赖注入 | 模板 | 高 | ★★★☆☆ |
| **Svelte** | Rich Harris (Vercel) | 编译时框架，无虚拟 DOM | 模板 | 低 | ★★★☆☆ |
### React
```javascript
// 函数组件 + Hooks —— React 的现代写法
import { useState } from 'react'

function Counter() {
  const [count, setCount] = useState(0)
  return <button onClick={() => setCount(count + 1)}>点了 {count} 次</button>
}
```
**特点：**
- 一切皆 JS（JSX 就是 JS 里写 HTML）
- Hooks 管状态和副作用（useState、useEffect、useMemo…）
- 社区最大，第三方库最多，招人最容易
- 灵活但不统一——同一件事有 N 种做法
**适用场景：** 大型应用、团队项目、需要丰富生态
### Vue
```plain text
<!-- 单文件组件（SFC）—— Vue 的标志 -->
<script setup lang="ts">
import { ref } from 'vue'
const count = ref(0)
</script>

<template>
  <button @click="count++">点了 {{ count }} 次</button>
</template>

<style scoped>
button { color: green; }
</style>
```
**特点：**
- 模板、逻辑、样式写在一个 `.vue` 文件里，结构清晰
- 响应式系统（ref / reactive）自动追踪依赖
- 官方提供全家桶（Vue Router、Pinia），选型少纠结
- 中文文档好，国内生态强（Element Plus、Ant Design Vue…）
**适用场景：** 中后台系统、快速开发、国内团队
### Angular
```typescript
// 组件 = 类 + 装饰器 —— 浓浓的 Java 风格
@Component({
  selector: 'app-counter',
  template: `<button (click)="count = count + 1">点了 {{ count }} 次</button>`,
})
export class CounterComponent {
  count = 0;
}
```
**特点：**
- 全家桶内置（路由、表单、HTTP、DI、RxJS）
- TypeScript 强制，规范严格
- 适合大型企业级项目，架构感强
- 学习曲线最陡
**适用场景：** 大型企业应用、强规范团队
### Svelte
```plain text
<!-- 最接近原生 HTML 的写法 -->
<script>
  let count = 0
</script>

<button on:click={() => count++}>点了 {count} 次</button>

<style>
  button { color: purple; }
</style>
```
**特点：**
- 编译时把响应式逻辑编译成原生 JS，没有运行时框架
- 代码量最少，写起来最爽
- 性能优秀（无虚拟 DOM 开销）
- 生态较小，大型项目案例少
**适用场景：** 个人项目、小型应用、追求极致性能和开发体验
### 新秀值得关注
| 框架 | 特点 |
| --- | --- |
| **Solid** | 类 React 语法，但编译时响应式（无虚拟 DOM），性能极强 |
| **Qwik** | 极致懒加载（Resumability），首屏近乎零 JS |
| **Preact** | 3KB 的 React 替代品，API 兼容 |
### UI 框架选型建议
```plain text
要生态最大、招人容易      → React
要上手快、中文生态好      → Vue
要强规范的企业级全家桶    → Angular
要极致性能和开发体验      → Svelte
```

## 三、② CSS 方案
> 怎么写样式？选择太多了，以下是主流方案：
| 方案 | 类型 | 特点 |
| --- | --- | --- |
| **Tailwind CSS** | 原子化 CSS | 在 HTML 里写 class，不用写 CSS 文件 ⭐ |
| **UnoCSS** | 原子化 CSS | 类 Tailwind，但更快更灵活（按需生成） |
| **CSS Modules** | 作用域 CSS | 每个组件的 class 自动加哈希，不冲突 |
| **Sass / Less** | 预处理器 | 支持变量、嵌套、Mixin 等 |
| **styled-components** | CSS-in-JS | 在 JS 里写 CSS（React 生态） |
| **vanilla-extract** | 零运行时 CSS-in-JS | TypeScript 写样式，编译时生成 CSS |
```html
<!-- Tailwind CSS 示例 -->
<button class="bg-blue-500 text-white px-4 py-2 rounded hover:bg-blue-600">
  点击
</button>
```
### CSS 方案选型建议
```plain text
新项目首选              → Tailwind CSS
追求极致性能            → UnoCSS
Vue/React 组件样式隔离  → CSS Modules
老项目 / 习惯传统 CSS   → Sass
```

## 四、③ 组件库（UI Component Library）
> 别人做好的按钮、表格、弹窗、表单…… 开箱即用。
### React 生态
| 组件库 | 出品 | 风格 | 适用场景 |
| --- | --- | --- | --- |
| **Ant Design** | 蚂蚁 | 企业级，功能全 | 中后台 ⭐ |

| **shadcn/ui** | 社区 | 复制源码到项目，完全可控 | 定制化项目 ⭐ |
| **Radix UI** | 社区 | 无样式基础组件 | 高度定制 |
| **Chakra UI** | 社区 | 简洁易用 | 快速开发 |
### Vue 生态
| 组件库 | 出品 | 风格 | 适用场景 |
| --- | --- | --- | --- |
| **Element Plus** | 饿了么 → 社区 | 经典中后台 | Vue 3 中后台 ⭐ |
| **Ant Design Vue** | 社区 | 和 Ant Design 同风格 | 中后台 |
| **Naive UI** | 社区 | TypeScript 友好，主题灵活 | 中后台 |

```plain text

Vue + 中后台       → Element Plus
Vue + 追求美观     → Naive UI
```

## 五、④ 状态管理
> 组件多了，数据怎么共享？props 层层传递太痛苦，需要全局状态管理。
### React 生态
| 工具 | 特点 | 复杂度 |
| --- | --- | --- |
| **Zustand** | 极简，几行代码就能用 ⭐ | 低 |
| **Jotai** | 原子化状态，适合细粒度 | 低 |
| **Redux Toolkit** | 官方推荐的 Redux 简化版 | 中 |
| **Redux** | 老牌，概念多（action/reducer/dispatch） | 高 |
| **React Context** | React 内置，简单场景够用 | 低 |
```javascript
// Zustand 示例 —— 就这么简单
import { create } from 'zustand'

const useStore = create((set) => ({
  count: 0,
  inc: () => set((s) => ({ count: s.count + 1 })),
}))

function Counter() {
  const { count, inc } = useStore()
  return <button onClick={inc}>{count}</button>
}
```
### Vue 生态
| 工具 | 特点 | 复杂度 |
| --- | --- | --- |
| **Pinia** | Vue 3 官方推荐，简洁好用 ⭐ | 低 |
| **Vuex** | Vue 2 时代的标准方案 | 中 |
```javascript
// Pinia 示例
import { defineStore } from 'pinia'

export const useCounterStore = defineStore('counter', {
  state: () => ({ count: 0 }),
  actions: {
    increment() { this.count++ }
  }
})
```
### 选型建议
```plain text
React → Zustand（简单场景）/ Redux Toolkit（复杂场景）
Vue 3 → Pinia（唯一推荐）
Vue 2 → Vuex
```

## 六、⑤ 上层框架 / Meta Framework
> 在 UI 框架之上，帮你搞定**路由、SSR、API、部署**等工程化问题。现代前端开发基本都用 Meta Framework。
| 框架 | 基于 | 核心能力 | 适用场景 |
| --- | --- | --- | --- |
| **Next.js** | React | SSR/SSG/ISR、App Router、API Routes、全栈 | React 项目首选 ⭐ |
| **Nuxt** | Vue | SSR/SSG、自动路由、模块生态 | Vue 项目首选 ⭐ |
| **Remix** | React | 嵌套路由、loader/action 数据模型 | 全栈 Web App |
| **Astro** | 不绑定 | 内容优先、Island 架构、多框架混用 | 文档站 / 博客 / 营销页 ⭐ |
| **SvelteKit** | Svelte | SSR/SSG、文件路由 | Svelte 项目首选 |
### Next.js（React 生态王者）
```bash
npx create-next-app@latest my-app --typescript --tailwind --app
```
```typescript
// app/page.tsx —— App Router 写法
export default async function Home() {
  const data = await fetch('<https://api.example.com/posts>') // 服务端获取数据
  const posts = await data.json()

  return (
    <ul>
      {posts.map(post => <li key={post.id}>{post.title}</li>)}
    </ul>
  )
}
```
**核心概念：**
- **SSR（服务端渲染）：** 服务器生成 HTML，SEO 好，首屏快
- **SSG（静态生成）：** 构建时生成 HTML，CDN 部署，最快
- **ISR（增量静态再生成）：** SSG + 定时刷新，兼顾性能和时效
- **Server Components：** 组件在服务端执行，JS 不送到客户端
- **API Routes：** 前后端一个项目搞定
### Nuxt（Vue 生态王者）
```bash
npx nuxi init my-app
```
```plain text
<!-- pages/index.vue —— 自动路由，文件即路由 -->
<script setup>
const { data: posts } = await useFetch('/api/posts')
</script>

<template>
  <ul>
    <li v-for="post in posts" :key="post.id">{{ post.title }}</li>
  </ul>
</template>
```
### Astro（内容站点神器）
```plain text
---
// src/pages/index.astro —— 默认零 JS 输出！
const posts = await fetch('<https://api.example.com/posts>').then(r => r.json())
---
<html>
  <body>
    <h1>博客</h1>
    {posts.map(post => <article>{post.title}</article>)}
    <!-- 只有需要交互的部分才加载 JS（Island 架构） -->
    <MyReactCounter client:visible />
  </body>
</html>
```
### 选型建议
```plain text
React 全栈应用          → Next.js
Vue 全栈应用            → Nuxt
博客 / 文档 / 营销页     → Astro
Svelte 项目             → SvelteKit
```

## 七、⑥ 跨平台方案
> 一套代码，多端运行（Web + 小程序 + App）。
| 框架 | 技术栈 | 目标平台 | 适用场景 |
| --- | --- | --- | --- |
| **React Native** | React | iOS / Android | 原生 App |
| **Flutter** | Dart | iOS / Android / Web / Desktop | 全平台 App |
| **Taro** | React / Vue | 小程序 + H5 + RN | 国内多端小程序 ⭐ |
| **uni-app** | Vue | 小程序 + H5 + App | 国内多端小程序 |
| **Electron** | Web 技术 | Windows / macOS / Linux | 桌面应用 |
| **Tauri** | Web + Rust | Windows / macOS / Linux | 轻量桌面应用 ⭐ |
### 选型建议
```plain text
做原生 App（国际）      → React Native 或 Flutter
做国内小程序多端         → Taro（React 团队）/ uni-app（Vue 团队）
做桌面应用              → Tauri（轻量）/ Electron（生态大）
```

## 十、一句话总结
- **选 UI 框架是最重要的决定** —— 它决定了后续所有选型
- **React 生态最大**，Vue 国内最流行，Angular 企业级，Svelte 最简洁
- **现代项目都用 Meta Framework**（Next.js / Nuxt），别再裸写 React/Vue 了
- **Tailwind + TypeScript** 已经是事实标准
- **Vite** 是当前构建工具的默认选择
